### Фикс #2 — тоннаж гантелей
`src/data.js` (рядом с `BW_EXERCISES`, ~строки 182–230):
```js
export const DUMBBELL_PAIR = new Set([
  "Жим гантелей на скамье 15°", "Жим гантелей сидя", "Разведение гантелей лёжа",
  "Махи гантелей в стороны", "Подъём гантелей хватом «молот»",
  "Болгарский сплит-присед с гантелями",
]);
export const loadUnits = (exName) => (DUMBBELL_PAIR.has(exName) ? 2 : 1);
// exerciseVolume теперь умножает нагрузку на units:
//   v + load * units * reps
```
- `24×5` парного жима → тоннаж **240** (было 120). ✓
- `setLoad`, `exerciseTop`, `exerciseE1rmBest`, `exercisePRList` **не тронуты** — там
  остаётся вес одной гантели (как пользователь вводит; PR/hero/e1RM не раздуваются).
- Подтягивания/Брусья: `units=1`, формула `bw−w` уже верна
  (помощь «+» уменьшает, утяжелитель «−» увеличивает) → объём `= (bw ∓ w) × повт`.

## Что осталось сделать (полные спеки — можно реализовать напрямую)

### Фикс #1 — чекбокс упражнения + персист формы между вкладками
**Проблема:** `App.jsx` (~строка 216) рендерит `{tab === 'log' && <Log .../>}` — при смене
вкладки `Log` размонтируется и весь стейт `form` (введённые веса/повторы + флаги `done`)
теряется. Чекбокса на уровне упражнения нет (только на подходах — `toggleDone`,
кнопка `.ft-set-check`).

**Требования:**
1. У каждого упражнения в форме — свой чекбокс в шапке `.ft-ex-h`. Клик → все подходы
   `done=true`; повторный → снять у всех.
2. Когда вручную отмечены ВСЕ подходы — чекбокс упражнения авто-«сделано».
   Состояние **вычисляемое**: `allDone = e.sets.length>0 && e.sets.every(s=>s.done)`.
   Отдельное поле `done` у упражнения НЕ вводить (единый источник истины — подходы).
3. Прогресс незавершённой тренировки (`tplId, date, form` с введёнными weight/reps и
   `done`, `editingId`) переживает смену вкладок и перезагрузку — localStorage,
   ключ `"strong-log:draft"`.

**Реализация (в `Log`, `src/App.jsx`):**
- Ленивый `useState` инициализатор для `form/tplId/date/editingId`, читающий
  `"strong-log:draft"` из localStorage (try/catch, `v:1`). Нет/битый → как сейчас
  (`tplId=templates[0].id`, `form=suggestForm(templates[0],sessions)`, `editingId=null`).
- `useEffect([form,tplId,date,editingId])` → пишет JSON-черновик в localStorage.
- В `commit()` после успешного `addSession` → `localStorage.removeItem("strong-log:draft")`.
- `toggleExDone(ei)`:
  ```js
  const c = structuredClone(form);
  const cur = c[ei].sets;
  const allDone = cur.length>0 && cur.every(s=>s.done);
  cur.forEach(s => { s.done = !allDone; });
  setForm(c);
  ```
  Таймер отдыха при массовом переключении **не** запускать (в отличие от одиночного
  `toggleDone`, который стартует таймер при включении одного подхода — его не менять).
- Чекбокс упражнения — `<button>` в `.ft-ex-h`; класс «вкл» при `allDone`. Стиль в духе
  `.ft-set-check`; при необходимости добавить CSS-класс(ы) в `export const CSS` (`data.js`).
- Не сломать: `startEdit` (done=false при загрузке сохранённой), `pick` (форма =
  `suggestForm(новый tpl)`, черновик обновляется), `cancelEdit`, add/del подходов и упражнений.

### Фикс #3 — «минус» в весе для BW-упражнений (Брусья/Подтягивания)
**Проблема:** поле веса — `<input type="number" inputMode="decimal">` (`App.jsx` ~875–878);
на мобильной цифровой клавиатуре нет «−», а утяжелитель Брусьев вводится как `−10`.

**Требование/реализация:**
- Только для BW-упражнений (`BW_EXERCISES.has(e.n)`) — кнопка-тумблер **«±»** рядом с полем
  веса, инвертирует знак текущего значения (в т.ч. пустого → `"-"`). `inputMode` оставить
  `decimal`, знак — кнопкой.
  ```js
  function toggleSign(ei, si) {
    const v = String(form[ei].sets[si].weight ?? "");
    setCell(ei, si, "weight", v.startsWith("-") ? v.slice(1) : ("-" + v));
  }
  ```
  Кнопка `disabled` когда `s.done`.
- Отрисовать «±» как input-adornment: обёртка `position:relative` вокруг `<input>`, кнопка
  `position:absolute` слева, у input левый padding. **НЕ** добавлять новую колонку в grid
  `.ft-set-log` (5 колонок: `# / вес / повт / галочка / удалить`). Для НЕ-BW — как раньше.
- CSS-классы обёртки/кнопки — в `export const CSS` (`data.js`), стиль проекта (акцент `C.accent`).
- ⚠️ Внедрять **после/вместе** с #1: тот же участок (set-row) правит и #1. Перечитать
  актуальный `App.jsx` перед правкой.

## Ключевые решения (зафиксированы, при желании поменять — скажи)
- **Парные гантельные (тоннаж ×2):** жим на скамье 15°, жим сидя, разведение лёжа, махи в
  стороны, «молот», болгарский сплит-присед. Гоблет/выпрыгивания — ×1 (в новой программе их нет).
- ×2 применяется **только к тоннажу/объёму**. «Рабочий вес», e1RM, таблица PR, hero-график
  остаются на весе одной гантели (то, что вводится и узнаётся).
- Подтягивания/Брусья — формула `(вес_тела ∓ помощь/утяж) × повт` (уже была верна).
- `«…«бабочка»»` → канон `Сведение рук в тренажёре` (существующее упражнение), не новое.

## Проверка при продолжении
```bash
npm install            # если node_modules нет (контейнер эфемерный)
npm run build          # должно быть exit 0
php -l api/lib/Exercises.php
# режим без бэкенда для ручной проверки UI:
VITE_API_BASE=local npm run dev
```
Проверить руками: тоннаж парного жима (24×5 → 240), чекбокс упражнения ставит все
подходы, данные не пропадают при переходе между вкладками, «±» на Брусьях вводит минус,
в форме появились новые упражнения с предзаполненными весами.

## Как продолжить пайплайном (опционально)
Скрипт пайплайна сохранён в репо: `docs/strong-log-pipeline.js` (полные спеки всех 4 фич
внутри). Чтобы доделать только #1 и #3, не трогая готовое #4/#2 — в скрипте ограничить
`buildOrder = ['f1','f3']` (и, при желании, планировать только эти фичи), затем запустить
через Workflow. Либо реализовать #1/#3 напрямую по спекам выше — они самодостаточны.
